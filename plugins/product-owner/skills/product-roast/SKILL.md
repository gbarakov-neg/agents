# Product Roast & Recommendations

Deliver a comprehensive product analysis with actionable recommendations.

## Trigger Conditions

Use this skill when:
- User asks to "roast", "review", "audit", or "analyze" a website or app
- User wants to improve UX, engagement, revenue, or conversions
- User asks "what's wrong with my site/app"
- User wants modernization advice
- Before any major redesign or feature planning

## Process

### Step 1: Deep Analysis

Examine the project thoroughly:

1. **Read the codebase** — understand the tech stack, architecture, and current state
2. **Analyze the UI** — look at components, layouts, styles, responsiveness
3. **Check the user flow** — trace the path from landing to conversion
4. **Review the content** — copy, messaging, value proposition clarity
5. **Assess performance** — bundle sizes, load patterns, optimization
6. **Evaluate SEO** — meta tags, structure, content strategy
7. **Check mobile** — responsive design, touch targets, mobile-specific UX

### Step 2: Write the Roast

Structure your roast with these sections:
- **First Impression**: What hits you in 0-5 seconds
- **The Good**: What's working (be specific, build trust before criticizing)
- **The Ugly**: What's broken, outdated, or hurting the business (be brutally honest but friendly)
- **The Missed Opportunities**: Revenue, engagement, and growth left on the table
- **The Verdict**: Overall assessment in 2-3 sentences

### Step 3: Deliver Recommendations

10-15 ideas, each with:
- Catchy title
- Specific implementation description (self-explanatory)
- Connection to a roast finding
- Expected impact
- Effort estimate (S/M/L/XL)
- Priority tier (Quick Win / High Impact / Strategic)

### Quality Checklist

Before delivering:
- [ ] Every recommendation references a specific finding from the roast
- [ ] Zero generic ideas that could apply to any website
- [ ] At least 3 ideas involve 2026-era tactics (AI, personalization, conversational UI, etc.)
- [ ] At least 2 ideas are revenue-focused
- [ ] At least 2 ideas are "wow, that's clever" unconventional
- [ ] Ideas are ordered by implementation priority
- [ ] Each idea is specific enough to hand directly to a developer
